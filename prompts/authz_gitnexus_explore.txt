<methodology>
1. **Enumerate routes**: grep for all route definitions across the repo:
   - JS/TS: `app.get`, `app.post`, `app.put`, `app.delete`, `router.get/post/put/delete`, `@Controller`, `@Get/@Post/@Put/@Delete` (NestJS)
   - Java: `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, `@RequestMapping`, `@RestController`
   - Python: `@app.route`, `@router.get/post`, FastAPI `@app.get/post`, Django-rest `APIView`/`ViewSet`
   - Go: `http.HandleFunc`, `mux.HandleFunc`, `gin.*`, `echo.*`
   - PHP: `Route::`, `Router::`, `$_GET`/`$_POST` dispatch
   - GraphQL: resolver methods / `@Query` / `@Mutation`
2. **For each endpoint handling an object reference** (path/param/query/body carrying an id — `{id}`, `:id`, `?id=`, `userId`, `orderId`, etc.), `read` its handler:
   - Does it use the request-controlled parameter to fetch an object (e.g. `req.params.id` → DB query / ORM `findById` / `findOne`)?
   - Is there an ownership/role guard on the handler or its call chain (`where userId = req.user.id` comparison, `@PreAuthorize`, `requireOwner`, role check on the fetched object)?
3. **Verdict**: no guard + takes an externally-controlled object reference → IDOR candidate.
</methodology>

`verdict` semantics:
- "vulnerable" = no ownership/role guard + externally-controlled object
  reference reaches another user's data (IDOR candidate).
- "safe" = you read the handler/call chain and confirmed it is protected or
  cannot reach another user's data (ownership guard present, uid taken from
  the session rather than the request, or the parameter only selects
  public/config data). Safe entries are archived for human review, NOT shown
  as vulnerabilities — emit them rather than silently dropping what you
  reviewed, so the review is auditable.
NEVER encode the verdict in `externally_exploitable`: it is a network
reachability tag (public-internet vs internal), fully independent of
vulnerable/safe.
</output>

<externally_exploitable_semantics>
**`externally_exploitable` is a REACHABILITY TAG, not an authentication requirement.**
- `true` = the endpoint is exposed to the public internet (reachable from outside via the app's nginx / API gateway). **Requiring login does NOT make it `false`** — an external attacker who holds any valid credential (or obtains one via an auth flaw) can still reach it. IDOR candidates are exercised through an authenticated session; if the endpoint itself is publicly exposed, set `true`.
- `false` = the endpoint is reachable only from an internal network / cross-service; an external attacker cannot reach it from the public internet at all.
- **"Requires login" ≠ `false`.** `authentication_required` and network reachability are two independent dimensions — a public API that requires login is still `externally_exploitable=true`. Do NOT infer `false` from "the attack needs a logged-in user"; that confuses authentication with reachability and drops PoCs for real public-facing IDORs.
</externally_exploitable_semantics>
